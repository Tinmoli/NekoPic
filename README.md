# NekoPic

一个用 Go 编写的随机图片服务。下载程序、放入图片即可使用，无需数据库。支持自定义分类、按设备选图、网页浏览、反向代理和 CDN，可用于随机壁纸、网站配图或个人图库。

- **直接运行**：首次启动自动生成配置、图库文件夹和网页文件。
- **分类灵活**：默认提供电脑和手机分类，也能添加自己的分类。
- **多种返回方式**：随机图片、JSON 图片信息、全部图片地址。
- **自带网页**：首页展示图库和接口说明，浏览页保持网站标题，图片居中显示。
- **日常维护方便**：定时检查图片变化，日志达到 100 MB 自动压缩。
- **基本安全防护**：限制请求次数、检查文件路径和图片格式，支持访问 IP 限制。

支持 JPEG、PNG、GIF、WebP。默认允许图片后缀与实际格式不同，不修改原文件名；不限制像素数，单张图片默认最多 50 MiB。程序不附带图库，也不提供网页上传功能。

## 下载

进入 [Releases 下载页面](https://github.com/Tinmoli/NekoPic/releases/latest)，下载适合系统的文件，使用时不需要安装 Go 或自行编译。

| 系统 | 下载文件 |
|---|---|
| Windows，常见 Intel / AMD 电脑 | `nekopic-windows-amd64.exe` |
| Windows ARM64 | `nekopic-windows-arm64.exe` |
| Linux x86-64 | `nekopic-linux-amd64` |
| Linux ARM64 | `nekopic-linux-arm64` |
| Linux ARMv7 | `nekopic-linux-armv7` |

`SHA256SUMS` 用于核对下载文件是否完整。GitHub 自动提供的 Source code 是源码，直接使用请选择上表中的程序文件。

## 开始使用

### Windows

1. 新建一个运行文件夹，把下载的程序放进去，可重命名为 `nekopic.exe`。
2. 双击一次，程序生成配置和文件夹后退出。
3. 把电脑图片放入 `view/pc`，手机图片放入 `view/pe`。
4. 再次双击，打开 [http://localhost:8505/](http://localhost:8505/) 即可使用。
5. 关闭服务时，在程序窗口按 **Ctrl+C**。

### Linux

把下载的文件重命名为 `nekopic`，放入运行目录，然后执行：

```sh
chmod +x ./nekopic
./nekopic
```

首次运行生成配置后退出。放好图片，再执行 `./nekopic` 启动。它在终端前台运行，需要长期运行时可交给 systemd 等服务管理工具。

### 运行目录

```text
运行目录/
├── nekopic.exe       # Linux 下为 nekopic
├── config.toml       # 配置文件
├── view/
│   ├── pc/           # 电脑图片
│   └── pe/           # 手机图片
├── web/              # 可修改的网页和样式
└── logs/             # 日志
```

所有相对文件路径都以**程序所在文件夹**为准。启动时保留已有配置和网页，不覆盖你的修改。

只读取分类文件夹第一层的图片，子文件夹内的图片不会被读取。新增、删除图片后默认最多等待 5 分钟更新，也可以重启立即更新。修改配置或网页模板需要重启，修改 CSS 后刷新网页即可。

默认监听 `0.0.0.0:8505`，允许其他设备连接。局域网设备使用 `http://服务器的局域网IP:8505/`，同时确认防火墙允许该端口。

## 常用配置

打开程序旁的 `config.toml`，修改已有项目，不要重复添加同名的 `[site]`、`[server]` 等配置段。完整示例见 [config.example.toml](config.example.toml)。

| 设置 | 作用 |
|---|---|
| `site.name` | 首页和图片浏览页的网站名称 |
| `site.icon_url` | 图标的 HTTP/HTTPS 地址；留空只显示名称 |
| `server.host` | `0.0.0.0` 允许其他设备连接；`127.0.0.1` 只允许本机连接 |
| `server.port` | 监听端口，默认 8505 |
| `base_url` | 留空返回相对图片地址；填写域名则返回完整地址 |
| `image.max_pixels` | 图片宽×高的上限，0 表示不限制 |
| `image.max_file_bytes` | 单张图片的字节数上限，默认 52428800 |
| `image.refresh_interval` | 检查图片变化的间隔，单位为分钟；0 表示只在启动时检查 |
| `security.allowed_ips` | 允许访问的 IP 范围，`[]` 表示不限制 |
| `security.allowed_hosts` | 允许访问的域名，`[]` 表示不限制 |

`base_url` 必须放在文件最上面的配置段之外。一般保持空字符串即可；如果外部程序需要完整图片链接，可以填 `https://img.example.com`，不要加子路径。

单个 IPv4 的访问限制示例是 `allowed_ips = ["192.168.1.5/32"]`，网段示例是 `["192.168.1.0/24"]`。不需要限制就保持 `[]`。

## 添加分类

在配置文件末尾添加：

```toml
[[categories]]
name = "acg"
```

把图片放入 `view/acg`，重启后即可访问 `/acg` 和 `/view/acg`。文件夹不存在时程序会创建它。需要指定其他位置时，在该分类下面添加 `directory = "其他路径"`。

分类名以小写字母开头，只能使用小写字母、数字、下划线和连字符，最长 32 个字符。最多支持 64 个分类，目录不能重复或互相包含。`api`、`auto`、`dm`、`view`、`test`、`health`、`assets`、`web`、`logs` 是程序保留的名字。

也可以把 `catalog.auto_detect` 改为 `true`：重启时自动识别 `view` 下含图片的新文件夹，检查通过后追加到配置中。该功能默认关闭，只在启动时识别新分类。以点开头的文件夹不会被识别。

## 图片接口

下列地址都支持 **GET 和 HEAD**。`/pc`、`/pe` 是默认分类，自定义分类使用相同规则。

| 地址 | 返回内容 |
|---|---|
| `/api` | 根据设备选择分类，默认电脑跳转 `/pc`、手机跳转 `/pe` |
| `/pc` | 随机电脑图片，302 跳转到图片文件 |
| `/pe` | 随机手机图片 |
| `/dm` | 从全部分类中随机选一张 |
| `/pc?return=json` | 图片地址、宽度、高度和格式 |
| `/pc?return=all` | 该分类全部图片地址，每行一个 |
| `/pc/文件名.jpg` | 指定图片，支持分段下载 |
| `/health/live` | 检查服务是否运行 |
| `/health/ready` | 检查图库是否可用，返回分类数量和图片总数 |
| `/test` | 返回 `Hello World` |

`return=json` 和 `return=all` 同样适用于 `/pe`、`/dm` 和所有自定义分类。`/api` 只负责跳转，不保留查询参数；需要 JSON 时直接访问分类接口。

JSON 返回示例：

```json
{
  "code": "200",
  "acgurl": "/pc/example.jpg",
  "width": "1920",
  "height": "1080",
  "size": "jpg"
}
```

所有字段都是字符串。`size` 表示图片格式，不是文件大小。`base_url` 留空时，`acgurl` 和全部图片列表使用相对地址；调用方需要根据服务域名补全。

在其他网页中引用随机图片：

```html
<img src="https://你的域名/api" alt="随机图片">
```

## 图片浏览页

| 地址 | 用途 |
|---|---|
| `/` | 首页和接口说明 |
| `/view/auto` | 根据设备选择分类后浏览 |
| `/view/dm` | 浏览全部分类中的随机图片 |
| `/view/pc`、`/view/pe` | 浏览指定分类 |
| `/view/acg` | 浏览自定义的 acg 分类 |

浏览页显示网站名称，图片保持比例，在窗口正中心显示，点击“换一张”继续浏览。直接打开图片文件时，标题由浏览器决定；需要固定网站名称时使用浏览页。

`auto` 是先按设备选分类，`dm` 是从全部分类中选图片。如果电脑和手机要使用其他分类，可在配置中设置：

```toml
[adaptive]
desktop = "pc"
mobile = "pe"
```

这两个分类必须存在，设置同时作用于 `/api` 和 `/view/auto`。

## 反向代理和 CDN

默认支持 Nginx、1Panel 的 OpenResty 和 CDN，无需开启反代开关。

同机反代的上游一般填写 `http://127.0.0.1:8505`，并设置：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Real-IP $remote_addr;
```

- `server.trusted_proxies` 填你自己的反代地址范围，默认信任本机。容器或其他机器上的反代，需填写程序实际看到的来源地址。
- `cdn.trusted_proxies` 填 CDN 厂商提供的回源地址范围，不使用 CDN 就留空。
- 默认从 `X-Forwarded-For` 读取访客 IP；也支持 `X-Real-IP`、`CF-Connecting-IP`、`True-Client-IP`、`X-Client-IP`。
- 使用 CDN 时，`server.client_ip_header` 保持 `X-Forwarded-For`，其他厂商专用头填在 `cdn.client_ip_header`。

可信代理配置与访客访问限制互相独立。不可信来源提供的 IP 请求头不会被采信，不要把整个互联网配置为可信代理。

随机接口、`/view/*` 和健康检查应绕过 CDN 缓存；实际图片文件可以缓存。部署后检查日志里的 `client_ip`，确认它是访客 IP，而不是反代服务器的 IP。

## 修改网页

| 文件 | 用途 |
|---|---|
| `web/home.html` | 首页 |
| `web/viewer.html` | 图片浏览页 |
| `web/error.html` | 浏览器看到的错误提示页 |
| `web/style.css` | 共用样式 |

网页使用 Go 模板，修改时保留 `{{...}}` 中的变量。各页可使用 `{{.Name}}` 和 `{{.Icon}}`；首页还有图片总数和分类列表，浏览页使用 `{{.Image}}` 和 `{{.Next}}`。可以参考生成的文件进行修改。

默认禁止网页执行脚本，允许直接编写样式。将 `security.inline_styles` 设为 `false` 后，样式只能通过本站样式表加载。

## 限流与日志

默认同一访客在连续 10 秒内最多请求 20 次随机图片，超过后暂停 30 秒并返回 HTTP 429。所有分类和图片浏览页共用次数；图片文件下载和健康检查不占次数。可通过 `[ratelimit]` 调整或关闭。

日志同时显示在程序窗口并写入 `logs`，文件名为生成时间。每个日志文件达到 100 MB（100,000,000 字节）后自动压缩为 `.log.gz`，继续写入新的文件。旧日志不会自动删除，可按需备份或清理。

`log.format = "text"` 方便直接阅读；`"json"` 适合日志工具。`log.level = "warn"` 可只记录警告和错误，减少正常请求日志。

## 常见问题

| 问题 | 处理方法 |
|---|---|
| 首次双击窗口立即关闭 | 正常行为。生成配置后，放好图片再运行 |
| 已有配置仍立即退出 | 在终端运行程序查看报错，检查配置和端口占用 |
| 打开页面但没有图片 | 检查对应分类文件夹、文件格式和大小，等待刷新或重启 |
| 其他设备无法访问 | 检查监听地址、防火墙和端口；其他设备不能使用 localhost |
| 能开首页但图片打不开 | 检查 base_url 是否填成了其他设备无法访问的地址 |
| 返回 403 | 检查允许访问的域名、IP 和可信代理设置 |
| 返回 429 | 等待封禁时间结束，或按需调整限流设置 |
| 修改同名图片后仍显示旧图 | 浏览器或 CDN 可能有缓存，建议更换文件名 |
| 开启自动识别后启动报错 | 检查分类数量和目录是否冲突，原配置不会因校验失败被改写 |

空分类的普通图片接口和 `return=all` 返回 404；`return=json` 返回 HTTP 200，但业务字段 `code` 为 `"500"`。所有分类都没有图片时，`/health/ready` 返回 503。

升级时先关闭服务，再替换程序文件。保留 `config.toml`、`view`、`web` 和 `logs`，无需重新放入图片或重新填写配置。
